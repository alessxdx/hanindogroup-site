    Regenerate it if the mappings below change. 404.html deliberately
    uses absolute paths (/assets/..., /photos/...) because Apache
    serves it at whatever URL the visitor asked for — do not change
    them to relative paths.
[ ] Check robots.txt reaches https://hanindogroup.com/robots.txt and
    sitemap.xml reaches https://hanindogroup.com/sitemap.xml, then
    submit the sitemap in Google Search Console.
[ ] Regenerate sitemap.xml whenever a page is added, deleted or
    renamed:

        perl tools/build-sitemap.pl

    It lists 48 URLs today. /search/, 404.html and the whole-department
    fire-fighting variant are deliberately left out, the same
    exclusions build-search-index.pl makes. A sitemap listing pages
    that no longer exist is worse than no sitemap at all, so run this
    before go-live and after any page change.
[ ] The canonical host is the BARE domain, https://hanindogroup.com
    (www 301s to it today). Every rel=canonical, og:url, sitemap URL
    and JSON-LD @id assumes that. If the hosting ever flips to www,
    all of them have to change together.
