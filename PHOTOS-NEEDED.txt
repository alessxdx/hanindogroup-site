HANINDO GROUP SITE — PHOTOS NEEDED
==================================================
Every slot below is already wired into a page. Drop a file with the
EXACT filename into the folder named in its section and it appears
automatically — no code changes needed. Until then the page shows a
styled "Photo needed" placeholder, so nothing looks broken.

Format: JPG for photos, PNG for logos. At least ~1000px wide for
heroes and ~800px for cards. Landscape suits heroes and cards.


FOLDER LAYOUT
--------------------------------------------------

Put a new photo in the folder for the site that uses it:

  photos/brand/               company logos and the group lockup
  photos/shared/hero/         heroes used by more than one site
  photos/shared/certificates/ ISO and SKK certificates
  photos/partners/            principal / supplier logos (27)

  photos/not-used/            on disk but referenced by no page

Folders with nothing in them yet hold a .gitkeep note saying which
filenames they are waiting for.

NOTE: the /fire-fighting/ section has its OWN photos folder
(/fire-fighting/photos/) which is already fully populated and is NOT
part of the layout above. Do not move those files and do not add
photos/fire-fighting/ — those pages reference their local folder as
plain "photos/...", so a root-level folder of the same name would
silently shadow nothing and just confuse the next person.

PARTNER LOGOS                                     [COMPLETE]
All principal logos live in /photos/partners/ — NOT in /photos/
directly. They appear as a static wall on the homepage and on the
/partners/ page. Filenames match the brand, for example:
  gilbarco.webp   opw1.webp   raasm.png   custom.png   itl.webp

Most are .webp, a few are .png. Any <img> must use the exact
extension. To replace one, keep the same filename AND extension,
otherwise the slot falls back to showing the brand name as text.

Lafon, PIUSI, TransTank and Transponder Technologies were dropped from
every wall at the business's request. Their logo files (lafon.webp,
piusi.svg, transtank.webp, tt.webp) have been deleted. Orpak and Invenco
were added to the homepage and /partners/ walls, so those lists now hold
19 brands (orpak.jpg and invenco.jpg were already in the folder).

Cebora was dropped from both walls at the business's request, and its
logo file (cebora.png) has been deleted.

The walls are no longer a grid of equal boxes. Each logo carries a tier
class that sets how large it is drawn — .t1 for the biggest principals,
.t2 for the rest — so the wall shows which relationships are the largest.
Sizing is height-driven: the tier fixes the logo's height and its width
follows its own shape, so the marks sit at natural, varied widths rather
than in equal boxes. The walls are also BANDED: each tier is wrapped in a
.tier row-group so a whole row is one size and a tier never shares a row
with another. To promote or demote a brand, move its cell into the other
tier's .tier group and change its class. Entries are listed by tier and
then alphabetically within it. (A third size, .t3, still exists in the
CSS for the customer walls; the principals wall stopped using it — the
list is short enough that two sizes read more cleanly.)

Current principals tiering (homepage + /partners/):
  t1  Airtec, Custom, Gilbarco Veeder-Root, HPA-Faip, ITL Technologies,
      RAASM, Red Jacket, TCS
  t2  Brain Bee, DOMS, Durapipe, Gasboy, Honeywell, Invenco, OPW,
      Orpak, Postec, Wincor Nixdorf
The Hanindo Citra page shows its own petroleum-relevant subset of these,
tiered the same way.

orpak.jpg and invenco.jpg were shipped with wide blank margins baked into
the canvas (Orpak filled only 43% of its height, Invenco 67%), so at a
fixed row height their marks rendered far smaller than neighbours like
Gasboy and Postec. Both files were trimmed to their content bounding box,
so they now fill the row height like every other logo. Trimming Invenco
also removed the faint off-white (#f7f7f7) margin that used to show as a
box on the white band. If either is ever replaced, supply a tightly
cropped file (no surrounding whitespace) so it renders at full size.

Most of these came from proxied search-result thumbnails, which are
small and, where the original had transparency, arrive with a grey

white on the affected files, and every logo was trimmed to its artwork
so the fixed-height cell scales them all to the same optical size.

The weakest files are adaro (200px) and mrt-jakarta (320px). They are

JD Sports and Wei Long Electronics keep their names visible: both marks
are monograms with no wordmark, the same exception JICT gets on the
Citra wall.

philippine-airlines.png was replaced with a complete file — full
sunburst, no clipping, plus the "Heart of the Filipino" tagline. The
earlier cropped version and its padding workaround are gone.

Both it and airasia.png came in around 270px wide, which is smaller than
the rest of the wall. Fine at 52px tall, soft if ever shown larger.

airasia.png is white on a solid red block, so its cell reads as a red
rectangle where every other cell is white artwork on white. Deliberate —
it is a standard AirAsia lockup — but a red-on-white version would sit
more quietly if one turns up.

sg-pools.png is portrait rather than landscape, so it renders narrower
than its neighbours in the fixed-height cell. burger-king.png is nearly
square, so it sits the same way.

idemia.png is the full lockup, chevron device and wordmark. The first
file supplied had the chevron sliced and was cut back to the wordmark
alone; the replacement is complete. It arrived white on IDEMIA purple,
which would have shown as a purple block in a wall of white cells, so it
was inverted to purple on white — the company's primary lockup, and the
same artwork, not a recolour of their brand.

SITA and Philippine Airlines are SVG, not PNG. Both raster versions were
cropped — SITA's final A and PAL's sunburst were sliced in the supplied
files — so they were replaced with public-domain vectors from Wikimedia
Commons. Being vector they cannot go soft or clip at any size, which
also settles the blur on the PAL logo. The partners wall already uses
SVG (opw.svg), so nothing special is needed to serve them.
